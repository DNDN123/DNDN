# 프로젝트 분석 — 기본 xv6에서 "자연어로 말하는 OS"까지

> 이 문서 하나만 읽으면 **이 프로젝트가 뭔지, 무엇을 어떻게 만들었는지** 이해할 수 있게 쓴 설명서입니다.
> 코드를 몰라도 읽을 수 있게, 큰 그림 → 세부 순서로 갑니다.

---

## 0. 한 줄 요약

> **xv6(작은 교육용 운영체제) 위에, "사람이 한국어로 말하면 OS가 알아듣고 실행하는" 시스템을 만들었다.**
> 말을 알아듣는 건 우리가 직접 학습시킨 작은 AI 모델이 하고, **실제 일(프로세스 관리·스케줄링)은 우리가 커널에 직접 구현한 OS 기능**이 한다.

---

## 1. 이게 뭔가요? (비유로)

평범한 OS는 이렇게 명령합니다:
```
$ killall cpu_burner        ← 정확한 명령어를 외워서 쳐야 함
```

우리가 만든 건 이렇게 됩니다:
```
$ 무거운 프로세스 정리해줘    ← 그냥 한국어로 말하면
killed heaviest pid 8 ...    ← OS가 알아듣고 실행
```

**비유**: OS를 "외국어만 알아듣는 직원"이라고 하면, 우리는 그 앞에 **통역사(AI)**를 세운 겁니다.
- 사장(사용자)이 한국어로 "무거운 거 정리해" 라고 말하면
- 통역사(AI)가 직원 언어로 "killheavy" 라고 번역하고
- **경비원(안전가드)**이 "위험한 명령 아닌지" 확인한 뒤
- 직원(OS 커널)이 실제로 일을 한다.

핵심은 **통역사는 회사 안(커널)에 들어오지 않는다**는 것. 통역사는 문 밖에 있고, 번역된 짧은 명령만 안으로 전달됩니다.

## 2. 기본 xv6 vs 우리가 만든 것

| | **기본 xv6 (출발점)** | **우리 시스템 (결과물)** |
|---|---|---|
| 스케줄러 | 라운드로빈 (모두 똑같이 한 바퀴씩) | **3단계 MLFQ** (바쁜 프로세스는 자동으로 우선순위↓) |
| 시스템콜 | 21개 (fork, exec, kill...) | +**15개 추가** (ps, setpri, reap, 스레드, futex...) |
| 명령 입력 | 정확한 명령어만 | **자연어 → 자동 번역·실행** |
| 프로세스 관리 | kill 하나하나 | ps / killall / killheavy / reap (한 번에 정리) |
| 안전장치 | 없음 | **안전가드** (init 보호, 위험명령 확인) |
| 동시성 | 프로세스만 | +**유저 스레드 + futex 동기화** |
| AI | 없음 | **직접 학습시킨 3B 모델** + 대화 기능 |

> 즉 출발점은 "교과서용 미니 OS"였고, 거기에 **진짜 OS 기능(스케줄러·시스템콜·동기화)을 직접 구현**한 뒤, 그 위에 **자연어 인터페이스**를 얹었습니다.

```
│   ┌──────────────┐   번역    ┌──────────────────┐             │
│   │  AI 모델       │◀────────│  브리지            │             │

│   "killheavy"           │  안전가드 통과                         │

★ AI는 점선 위(호스트)에만 있고, 커널 안에는 절대 안 들어감.
  커널은 "killheavy" 같은 작은 명령만 받음 — AI가 있었는지조차 모름.
```

## 4. 구성 요소 하나씩

### A. 커널 (진짜 OS 부분 — `os/kernel/`)
우리가 **직접 C로 구현**한 OS 알맹이. AI 없이도 완결된 운영체제.
- **3단계 MLFQ 스케줄러** (`proc.c`): 프로세스를 HIGH/MID/LOW 3큐로 관리.
  CPU를 많이 쓰면 자동으로 아래 큐로 강등(demotion), 주기적으로 다시 끌어올림(boost).
- **15개 신규 시스템콜**: `ps`(프로세스 목록), `setpri`(우선순위 변경), `reap`(좀비 정리),
  `forkpri`(특정 큐에 생성), `thread_create/join`(스레드), `futex_wait/wake`(동기화) 등.
- **안전한 멀티코어**: 락(`wait_lock`, `boost_lock`)으로 여러 CPU 동시 접근 보호.

### B. 유저 프로그램 (`os/user/`)
커널 기능을 쓰는 명령어들. `ps`, `killall`, `killheavy`, `reap`, `uptime`, `sysinfo`,
그리고 **`ask`**(자연어를 브리지로 보내는 다리), `nlrun`(특정 큐에서 작업 실행),
`cpu_burner`/`io_burner`(부하 테스트용 작업).

### C. AI 모델 (`ml/`)
- 베이스: **Qwen2.5-3B** (작은 범용 언어모델)
- 거기에 **우리가 직접 파인튜닝**(LoRA)해서 "자연어 → OS 인텐트" 전문가로 만듦.
- 정확도: 명령 분류 **98.2%**, 큐 힌트 **99.4%** (테스트 1854개 측정).
- 인텐트 20종: `cpu_burner`/`ps`/`kill`/`killheavy`/`reap`/`setpri`/`explain`/`reject`...

### D. 호스트 브리지 (`host/`)
AI와 커널을 잇는 파이썬 코드 (커널 밖).
- `nlos.py` — 한 방에 실행 (백엔드 선택 + 모델 + 브리지)
- `nlbridge.py` — xv6 콘솔을 감싸 자연어를 가로채고, 번역된 명령을 자동 입력
- `model_server.py` — 학습한 모델을 OpenAI 호환 서버로 띄움 (맥 MPS / 윈도우 GPU 둘 다)
- `executor.py` — 인텐트를 xv6 명령으로 변환 + **안전가드** + 대화 응답(`chat`)

## 5. 동작 예시 — "무거운 프로세스 정리해줘"를 따라가 보기

```
1. 사용자가 xv6 콘솔에 입력:  무거운 프로세스 정리해줘
2. xv6 셸: "무거운"이라는 프로그램이 없네 → "exec 무거운 failed" 출력
3. 브리지: 그 줄을 가로채 "이건 자연어구나" 판단 → AI 모델에 번역 요청
4. AI 모델:  {"cmd":"killheavy", ...}  (인텐트 JSON 반환)
5. 안전가드: killheavy는 위험명령 → 경고 후 허용 (init은 절대 안 죽임)
6. 브리지: xv6 콘솔에 "killheavy" 자동 입력
7. 커널: 실제로 가장 무거운 프로세스를 찾아 종료
   → "killed heaviest pid 8 (cpu_burner, run_ticks=405)"
```

**일반 대화**도 됩니다 (명령이 아니면 모델이 직접 답):
```
타임 슬라이스 설명해줘  → [assistant] 타임 슬라이스는 프로세스 실행 시간을 나눈 단위야.
```

## 6. OS 개념이 어디에 들어갔나 (과제 핵심)

과제 필수 조건: "운영체제 개념을 직접 설계·구현할 것". 우리는 **5개 이상**을 커널에 직접 구현했습니다.

| OS 개념 | 어디에 |
|---|---|
| **스케줄링** | 3단계 MLFQ (`proc.c`의 `scheduler()`) — 강등/승급/라운드로빈 |
| **프로세스** | fork/exec/exit + ps/kill/killall/killheavy/reap |
| **시스템콜** | 기본 21개 위에 15개 직접 추가 (6곳 등록) |
| **동기화** | 스핀락(`wait_lock`/`boost_lock`) + **futex** (사용자 동기화) |
| **스레드** | `thread_create/join/exit` (주소공간 공유) |
| **IPC** | 호스트↔게스트 콘솔 왕복 채널 |

> AI는 "리눅스에서 돌아간다" 수준의 껍데기가 아니라, **OS 알맹이는 우리가 직접 짠 것**.
> AI를 떼어내도 xv6 커널 + 명령어들은 그 자체로 완결된 운영체제입니다.

## 7. 핵심 설계 원칙

1. **AI는 커널에 절대 안 들어간다.** 번역만 호스트에서 하고, 커널엔 작은 명령(JSON 인텐트)만 전달.
   → 커널은 가볍고 빠르게 유지. (xv6는 128MB로 도는데 AI는 6GB — 애초에 못 넣고, 넣을 이유도 없음)
2. **AI가 틀려도 OS가 자가 교정.** AI가 작업을 엉뚱한 큐에 넣어도, MLFQ가 몇 틱 안에 올바른 큐로 강등.
3. **위험은 가드가 막는다.** init(pid 0·1) 종료 거부, 파괴적 명령(kill/rm/killall) 확인 게이트.
4. **AI 없이도 동작.** 모델·네트워크가 죽어도 규칙 기반 폴백으로 데모가 안 깨짐.

## 8. 무엇을 검증했나

- **커널 정확성**: xv6 공식 테스트 `usertests` **61개 전부 통과** (클린 빌드 3회 반복 안정).
- **발견·수정한 진짜 버그**: MLFQ 스케줄러 **기아(starvation)** 버그 — 같은 우선순위 고인덱스
  프로세스가 영영 실행 안 되던 문제를 **레벨 내 라운드로빈**으로 수정 (fork 폭주 테스트 통과).
- **AI 정확도**: 1854개 테스트로 명령 98.2% / 큐 99.4%.
- **호스트 로직**: 오프라인 자동 테스트 55종 통과 (가드/매핑/대화 등).
- 자세한 검증 기록: [`verification-report.md`](verification-report.md)

## 9. 솔직한 한계

- **자연어가 일반 명령어로 시작하면**(예: `ls 정리해줘`) 셸이 그 명령으로 실행 → 이땐 `ask` 접두 사용.
- **일반 대화는 "일부"만** — "설명해줘"·잡담은 모델이 답하지만, "프로세스가 뭐야"류는 모델이 ps로 분류해 실행될 수 있음 (인텐트 분류 모델의 특성).
- **xv6 콘솔이 부하 중 입력 바이트를 가끔 떨굼** — 모델이 복원해서 결과는 맞지만 화면이 잠깐 깨질 수 있음 (xv6 콘솔 내재 한계).
- **범위 밖**(xv6에 기능 자체가 없음): 네트워크, 사용자/권한, 패키지 매니저, 프로세스 일시정지.

## 한 줄 결론

> **"작은 교육용 OS(xv6)에 진짜 OS 기능을 직접 구현하고, 그 위에 직접 학습시킨 AI로 자연어 인터페이스를 얹은 시스템."**
> OS는 우리가 만든 알맹이, AI는 그 앞의 통역사 — 둘의 역할이 깔끔히 분리된 게 이 프로젝트의 핵심입니다.
