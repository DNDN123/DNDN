06 · INTEGRATION FIXES

07 통합 중 발견한 K1~K4

슬라이스 단독일 땐 안 보이고 합치는 순간 드러난 버그 — 코드에 K1~K4 fix 라벨.

K1 allocproc 필드 누수

슬롯 재사용 시 traced/syscall_count[]/is_thread 미초기화 → 직전 입주자 trace 상태 누수, dump 쓰레기.

K2 syscall_count 오버플로

minju 원본 배열 32 → 통합 후 35번까지 확장. 32 → 64 로 확장 (5개 파일).

K3 fork 시 traced 미상속

tracetool on 후 자식 프로세스 추적 누락 → fork()/forkpri() 둘 다 traced 상속 명시.

K4 어댑터 priority 범위

setpriority(0..20) 가정 → 0..2 정렬, SPAWN whitelist 도 없는 바이너리 제거.

2차 코드·보안 리뷰 (2026-05-28~29)

07+ K5~K7 — race · 보안

K5 thread/main 종료 race

main 이 자식 thread 보다 먼저 freeproc → 공유 페이지 kfree → page-use-after-free.

tgroup live thread 스캔 → thread_freepagetable 다운그레이드. 회귀 재현 thread_race.c.

K6 thread_bridge injection

Solar 응답 "ls\nkill 1" 이 shlex.split 에서 \n 공백 처리 → whitelist 우회, init kill.

\n \r ; & | ` $( 전부 차단.

K7 process_bridge 동일 결함

SPAWN intent 에 같은 newline 분리 결함 — 보안 가드가 두 어댑터에 일관 적용 안 됨을 드러냄.

guard() SPAWN 분기에 동일 차단 적용.

교훈: LLM 출력을 셸 stdin 으로 직접 흘리는 경로는 프롬프트 인젝션 = 명령 인젝션. whitelist 만으로 부족하고 메타문자·개행 차단이 함께 필요.

09 · KNOWN ISSUES

12 알려진 환경 의존성

통합 코드 자체 결함은 아니지만 평가 환경에 따라 결과가 달라질 수 있는 항목.

usertests reparent2 — 환경 차이

/mnt/c(9P FS)에서 fork bomb cleanup 100ms window 초과로 실패, /root(ext4)에서는 ALL PASSED. → 평가는 Linux native FS 권고.

userspace thread 라이브러리 미통합

thread.c/mutex.c 등 추상화는 xv6 안에서 syscall 만으로 충분 — _sources/jinhwan/ 에 보존.

haneol 단독 테스트 미포함

mlfq_bench, priority_test 등 단독 테스트는 통합 트리 제외, _sources/ 보존.

eval stderr 가림 → 패치 완료

5/26 무음 실패 원인(>/dev/null)을 5/27 stderr 분리 캡처로 해결, 재발 방지.
