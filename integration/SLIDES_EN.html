01 · OVERVIEW

01 Project Overview

The goal is to merge the xv6 slices that four people developed each on their own GitHub branch into a single buildable tree. The original branches are only read via git archive and not a single byte is modified.

Core Principles

  • Original-branch protection — no push / commit / new branches
  • Single entry point — host NL is the single nl_shell.py
  • API key sanitize — environment variables only, no hardcoding
  • Roll-back capable — originals preserved in _sources/

Final Deliverables

  • xv6-riscv/ — integrated build tree (kernel + user + workloads)
  • host/ — Solar Pro 3 LLM Python bridge (3 layers)
  • MERGE_NOTES.md — conflict-decision record (K1~K7)
  • docs/charts/integration/ — 5 workloads × 3 modes evaluation

06 · INTEGRATION FIXES

07 K1~K4 Found During Integration

Bugs that were invisible for a standalone slice and surfaced the moment they were merged — labeled K1~K4 fix in the code.

K1 allocproc field leak

On slot reuse, traced/syscall_count[]/is_thread were left uninitialized → trace state of the previous occupant leaked, garbage dump.

K2 syscall_count overflow

minju's original array of 32 → after integration it extended up to number 35. Expanded 32 → 64 (5 files).

K3 traced not inherited on fork

After tracetool on the child process was not traced → both fork()/forkpri() now explicitly inherit traced.

K4 adapter priority range

Assumed setpriority(0..20) → aligned to 0..2, and the SPAWN whitelist also removed nonexistent binaries.

2nd code·security review (2026-05-28~29)

07+ K5~K7 — race · security

K5 thread/main teardown race

main runs freeproc before the child thread → shared page kfree → page-use-after-free.

Scan tgroup for live threads → downgrade thread_freepagetable. Regression reproducer thread_race.c.

K6 thread_bridge injection

Solar response "ls\nkill 1" — shlex.split treats \n as whitespace → whitelist bypass, init kill.

\n \r ; & | ` $( all blocked.

K7 process_bridge same flaw

SPAWN intent had the same newline-splitting flaw — revealed that the security guard was not applied consistently across both adapters.

Same blocking applied to the guard() SPAWN branch.

Lesson: any path that pipes LLM output directly into shell stdin makes prompt injection = command injection. A whitelist alone is not enough — metacharacter·newline blocking is needed together.

LLM FOR OS — IDENTITY

08 Host 3-Layer Separation

So that the "LLM for OS" identity is not diluted by free-form chat, the host tools are separated into 3 layers by role.

LayerToolRoleIn evaluation
Hot pathnl_shell.py + adapters/*natural language → MLFQ queue integer reduction (main demo)✅
Cold pathops/supervisor.pynatural-language queries on MERGE_NOTES·eval·K-fix·syscall (5-stage refusal gate)✅ auxiliary
Dev pathdev_chat.pyfree-form chat REPL — developer convenience❌ intentional

Hot-path output is limited to a 2-bit queue level (0/1/2) — the LLM is a "translator", while execution·management stays in the OS layer. This is not a thin LLM wrapper.

09 · KNOWN ISSUES

12 Known Environment Dependencies

Not defects in the integration code itself, but items whose results may vary depending on the evaluation environment.

usertests reparent2 — environment difference

On /mnt/c (9P FS) the fork-bomb cleanup exceeds the 100ms window and fails; on /root (ext4) it is ALL PASSED. → evaluation recommended on Linux native FS.

userspace thread library not integrated

Abstractions like thread.c/mutex.c — syscalls alone are sufficient inside xv6 — preserved in _sources/jinhwan/.

haneol's standalone tests not included

Standalone tests like mlfq_bench, priority_test are excluded from the integration tree, preserved in _sources/.

eval stderr suppressed → patch done

The cause of the 5/26 silent failure (>/dev/null) was resolved on 5/27 with separate stderr capture, preventing recurrence.
