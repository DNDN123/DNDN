01 Project Overview

The goal was to merge the xv6 slices that four team members developed on their respective GitHub branches (origin/hyunsung, origin/minju, origin/jinhwan, origin/haneol) into a single buildable tree. The original branches are only read via git archive and are kept in a state where not a single byte was modified.

Core Principles

  • Original-branch protection — no push / commit / new-branch creation
  • Single entry point — the host NL interface is one file, nl_shell.py
  • API-key sanitize — environment variables only, no hardcoding
  • Roll-back capable — originals preserved under _sources/

Final Deliverables

  • xv6-riscv/ — integrated build tree (kernel + user + workloads)
  • host/ — Python bridge for Solar Pro 3 LLM integration
  • MERGE_NOTES.md — 281-line record of conflict decisions
  • docs/charts/integration/ — evaluation results for 5 workloads × 3 modes

03 4-Team Slices — Contributions

Each team's slice covers a different area, but because they all touch the same struct proc, syscall.c, and sysproc.c, conflicts were inevitable. The following are the contributions adopted into the integration.

hyunsung Scheduler / MLFQ

Role: base tree, 3-level MLFQ scheduler, NL-based priority hints.

  • Kernel: 3-level MLFQ (HIGH / MID / LOW), aging, demote
  • User: nlrun, wrunner, cpu/io/mixed_burner, rrunner, diagprog
  • Workloads: 6 types (cpu_heavy, io_heavy, mixed, three_way, realprog, stress)
  • Host: nl_shell.py single entry point + Solar prompts

minju Syscall Trace

Role: collect per-pid / per-syscall statistics from a single hook point for all syscalls.

  • Add traced, syscall_count[64], syscall_errors[64] to struct proc
  • 3 syscalls: sys_trace_on / off / stats
  • User: tracetool on / off / dump commands
  • dump output is JSON → integrates naturally with host LLM analysis

jinhwan Thread / Futex

Role: kernel-level threads + user-space synchronization primitives.

  • kthread_create / join / exit, kfutex_wait / wake
  • Page-table sharing: uvmshare, thread_freepagetable (vm.c)
  • Global futex_lock + is_thread, tgroup fields
  • User: threadtest (4 scenarios: shared mem / 4-thread / mutex / condvar)

haneol Process (ps / sysinfo)

Role: system-visibility tools. The priority slice overlapped with hyunsung and was DROPped.

  • sys_ps — 6-column output: pid/ppid/state/prio/sz/name
  • sys_sysinfo — freemem + nproc
  • Rewrote setprio.c — changed to call setpri(pid, 0..2)
  • DROP: sys_trace, sys_setpriority, sys_getpriority

05 Key Conflict Decisions

File-level conflicts can be resolved by a simple merge, but conflicts whose semantics overlap require choosing one side. Each decision's rationale was either quantitative verification or feature richness.

Conflict AreaWinnerReason
MLFQ scheduler hyunsung quantitatively verified; the 3-level queue is more refined than haneol's 0..20 priority
0..20 priority (haneol) DROP unified to hyunsung's setpri(0..2). setprio.c was rewritten
trace syscall (minju vs haneol) minju richer per-syscall statistics, JSON output format
kernel/syscall.c hooking minju added as a trace-hook patch on top of the hyunsung dispatch
kthread_* functions jinhwan unique functionality, appended in an area separate from MLFQ
host NL entry point hyunsung nl_shell.py single entry, the rest modularized into adapters/
Solar API key (jinhwan original plaintext) sanitize switched to the UPSTAGE_API_KEY env var, added a fallback when the key is absent

Items DROPped from the haneol slice

sys_trace (22)

Semantically overlaps with minju's trace_on/off/stats and is functionally weaker.

sys_setpriority (24)

The 0..20 scheme doesn't fit MLFQ. Replaced with setpri(0..2).

sys_getpriority (25)

hyunsung's getstats provides richer information.

06 K1~K7 Fixes During Integration / Review

The 7 fixes caught during integration and review are tagged in the code with K1~K7 fix labels. All are bugs that were invisible while a slice stood alone and only surfaced the moment they were merged. K1~K4 came from the first integration (2026-05-26), K5 from the second code review (thread teardown), and K6/K7 from the second security review (prompt-injection bypass).

K1 allocproc field leak

Symptom: tracetool dump produced garbage output — leaking the trace state of the previous slot occupant.

Cause: when a proc-table slot is reused, traced, syscall_count[], syscall_errors[], is_thread, tgroup were not initialized.

Location: kernel/proc.c:170, 177

K2 syscall_count array overflow

Symptom: index overflow starting at SYS_settrace=32.

Cause: minju's original assumed up to SYS_close=21, so the array size was 32. After integration it extends up to number 35.

Patch: expanded 32 → 64 (5 files).

K3 traced flag not inherited on fork

Symptom: after tracetool on in the shell, a child process launched afterward was not traced.

Patch: explicitly set np->traced = p->traced in both fork() and forkpri().

Location: kernel/proc.c:327, 935

K4 host adapter priority range

Symptom: process_bridge.py assumed setpriority(pid, 0..20).

Patch: aligned to the 0..2 range, and updated SPAWN_WHITELIST by removing priority_test, trace_test, sysinfo_test which are not in the integration tree.

Location: host/adapters/process_bridge.py:55, 85, 155

K5 thread/main teardown-order race

Symptom: if main (is_thread=0) is freeproc'd before its child threads, the shared pages get kfree'd, causing a page-use-after-free.

Patch: added a scan for live threads in the same tgroup to freeproc → when found, downgrade to thread_freepagetable (unmap only). A leak is possible but safer than corruption.

Regression reproduction: user/thread_race.c + the K5 case in sanity_check.sh.

K6 thread_bridge newline injection

Symptom: a Solar response "ls\nkill 1" — in shlex.split the \n is treated as whitespace → the whitelist validates only "ls", and both lines flow into xv6 stdin, bypassing init kill.

Patch: in guard_cmd, block all of \n \r ; & | ` $(.

Location: host/adapters/thread_bridge.py:guard_cmd

K7 process_bridge same injection

Symptom: the same newline-splitting flaw in the SPAWN intent — the same defect class existed redundantly in a separate adapter (the security guard was not applied consistently).

Patch: block the same metacharacters in the SPAWN branch of guard().

Location: host/adapters/process_bridge.py:guard SPAWN

08 How to Run (Cold-start)

A procedure laid out so that even someone receiving the integration tree for the first time can follow it directly. WSL2 Ubuntu or native Linux is required.

  1. Install Prerequisites

    You need the riscv toolchain + qemu + python3 venv.

    sudo apt update
sudo apt install -y gcc-riscv64-unknown-elf qemu-system-misc python3-venv

  2. Host Python Environment (one time only)

    Create a venv in integration/host and fill in the Solar API key in .env.

    cd integration/host
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# replace your_api_key_here in .env with your actual Upstage Solar key

  3. Build xv6

    Takes about 30 seconds. The build is OK once both kernel/kernel and fs.img are generated.

    cd integration/xv6-riscv
make clean && make
ls kernel/kernel fs.img

  4. Live 4-team demo after QEMU boot

    Demonstrate all 4 slices consecutively within a single QEMU session.

    make qemu CPUS=2          # $ prompt after boot

# [hyunsung] Scheduler — natural-language hint passed down to the queue level
$ nlrun 2 cpu_burner 50000
TRACE tick=… pri=2 …
EXIT  … final_pri=2

# [minju] Syscall trace — all syscalls hooked at a single point
$ tracetool on
$ ls
$ tracetool dump
{"pid":…,"traced":1,"total":…,"calls":{"fork":…,"exec":…,…}}

# [jinhwan] Thread — kthread + futex working correctly
$ threadtest
test 1: shared memory ... OK (counter=200000)
test 2: 4 threads ... OK
test 3: mutex exclusion ... OK
test 4: condvar producer/consumer ... OK (sum=499500)

# [haneol] Process — sys_ps + setpri integrated
$ ps
PID  PPID  STATE    PRIO  SZ        NAME
1    0     sleep    1     12288     init
…
$ setprio 1 2
OK pid=1 level=2

# [integration] background queue + LOW priority + zombie reaping
$ bgq bgq.txt
BGQ start echo
job1_started
BGQ done echo pid=4 exit=0
…
BGQ all_done 3

# Quit QEMU: Ctrl-A x

  5. Host LLM analysis — Solar Pro 3 integration

    Move xv6 output to the host and stream it for Solar to analyze.

    # (a) system diagnosis — diagprog output → identify starvation
$ python nl_shell.py --diagnose-from /tmp/diag.txt
  summary    : 3 processes healthy, 1 stuck at LOW
  ⚠ concern  : pid=5 stuck at priority=2 with run=200
  → action   : setpri 5 0

# (b) tracetool dump → classify process-behavior patterns
$ python nl_shell.py --analyze-tracetool /tmp/tracedump.json
  verdict : spawner
  summary : Process performed many fork/exec — shell-like
  → suggested queue: 0 (interactive launchers benefit from HIGH)

# (c) natural language → xv6 command dry-run
$ python nl_shell.py --once "Run a heavy job in background"
[nl_shell] → xv6 command: nlrun 2 cpu_burner 2000000

# (d) full automated demo (process adapter, stdin auto-injected)
$ python nl_shell.py --mode process
> show processes
[xv6 response] PID …
> set process 5 to low priority
[xv6 response] OK pid=5 level=2

  6. Re-run the quantitative evaluation matrix (optional)

    5 workloads × 3 modes, takes about 8 minutes. Results go under docs/charts/integration/.

    cd integration/host
source venv/bin/activate
XV6_DIR=../xv6-riscv \
OUT_ROOT=../../docs/charts/integration \
  ./run_eval_matrix.sh

cat ../../docs/charts/integration/combined_report.txt

⚠️ Note on the /mnt/c path: running QEMU on top of a Windows mount is slower than /root (ext4), so some workloads time out with no ALL_DONE. Increase the QEMU_TIMEOUT environment variable, or it is recommended to run evaluation on a Linux-native FS such as /root/integration-test.

09 Known Risks / Environment Dependencies

These are not defects in the integration code itself, but items whose results can vary depending on the evaluation environment.

usertests reparent2 — environment difference

Behavior: in usertests -q, #27 reparent2 gives fork failed on /mnt/c but ALL TESTS PASSED on /root.

Cause: the 9P FS + virtio-blk on /mnt/c can't finish within the 100ms fork-bomb cleanup window.

Response: recommend running evaluation/demos on ext4 such as /root/integration-test.

jinhwan thread userspace library not integrated

userspace abstractions such as thread.c / mutex.c are not included in the integration tree. The judgment was that within xv6 the syscalls alone are sufficient. They are preserved in _sources/jinhwan/.

haneol standalone test programs not included

mlfq_bench.c, priority_test.c, trace_test.c, sysinfo_test.c are for standalone testing — not in the integration tree, preserved in _sources/.

run_eval_matrix.sh hid stderr → patched

Previously it hid errors with >/dev/null 2>&1 (the cause of the 5/26 silent failure), but a 2026-05-27 patch captures stderr separately. The same silent failure does not recur.
