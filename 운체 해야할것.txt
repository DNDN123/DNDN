  프로젝트 목표 요약
  "자연어로 OS를 다루는 지능형 셸"
  - 사용자 입력 → Solar API(LLM) → 명령 해석 → OS 레이어가 실행  - OS 컴포넌트를 직접 구현해야 LLM 래퍼로 안 보임

  ---
  현재 만들어진 것 (너 작업분 - 스레드 파트)

  ┌───────────────────────────┬──────────────────────────────────────────┬─────────┐
  │           파일            │                   내용                   │ 완성도  │
  ├───────────────────────────┼──────────────────────────────────────────┼─────────┤
  │ src/thread/thread.c       │ clone() 기반 스레드 생성/종료/조인       │ ✅ 완성 │
  ├───────────────────────────┼──────────────────────────────────────────┼─────────┤
  │ src/thread/mutex.c        │ futex 기반 뮤텍스 (빠른 경로: 원자 CAS)  │ ✅ 완성 │
  ├───────────────────────────┼──────────────────────────────────────────┼─────────┤
  │ src/thread/condvar.c      │ futex 기반 조건변수 (lost wakeup 방지)   │ ✅ 완성 │
  ├───────────────────────────┼──────────────────────────────────────────┼─────────┤
  │ src/worker/worker_pool.c  │ 우선순위 큐 + 스레드풀 (HIGH/NORMAL/LOW) │ ✅ 완성 │
  ├───────────────────────────┼──────────────────────────────────────────┼─────────┤
  │ src/diag/diag_collector.c │ /proc, dmesg 병렬 수집 → LLM 전달용 포맷 │ ✅ 완성 │
  ├───────────────────────────┼──────────────────────────────────────────┼─────────┤
  │ test/test_thread.c        │ 위 전체 테스트                           │ ✅ 완성 │
  └───────────────────────────┴──────────────────────────────────────────┴─────────┘

  네 파트는 사실상 거의 다 됐어요.

  ---
  아직 없는 것 (팀 전체가 만들어야 함)

  [사용자 자연어 입력]
          ↓
  [Solar API HTTP 클라이언트]  ← 아직 없음
          ↓
  [LLM 응답 파서 → 명령어 추출]  ← 아직 없음
          ↓
  [프로세스 매니저]  ← 전한얼 파트, 아직 없음
    fork() / exec() / wait()
    백그라운드 잡 큐
    좀비 프로세스 회수 (SIGCHLD)
          ↓
  [스케줄러]  ← 조현성 파트, worker_pool과 연동 필요
          ↓
  [진단 결과 → Solar API 전달 → 분석 출력]  ← diag_collector는 있는데 연결이 없음

  핵심 메인 셸 (main.c / shell.c)가 없어요.

  ---
  일정 기준으로 지금 뭘 해야 하나

  지금 W12 단계 (자체 작업 관리자 + 스케줄러 통합) 인데:

  당장 필요한 것:

  1. src/shell/shell.c — 메인 루프
  while(1) { 입력 받기 → Solar API 호출 → 명령 실행 → 결과 출력 }
  2. src/llm/solar_client.c — Solar API HTTP 호출
    - libcurl 사용해서 Solar API에 POST
  3. src/process/job_manager.c — 전한얼 파트 (fork/exec/wait)
    - 백그라운드 잡 관리, SIGCHLD 처리
  4. worker_pool ↔ job_manager 연동 — 조현성 파트의 스케줄러가 너의 worker_pool을 써야 함

  ---
  한 가지 중요한 점

  문서엔 "운영체제: xv6"라고 되어 있는데, 지금 코드는 완전히 Linux 기반이에요 (clone(), mmap(), /proc 등 Linux 전용). xv6 안에서는 이 코드가 돌아가지 않아요.

  팀이 Linux/WSL에서 구현하기로 방향을 바꾼 건가요, 아니면 xv6에 이식해야 하나요? 방향에 따라 남은 작업이 크게 달라져요.
